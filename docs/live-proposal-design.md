# iPhone 模拟器：真实模型生成单文件修改提案

## 本轮要证明什么

在现有已验证的模拟器原型上，用户输入一句话后，由真实模型而非预置字符串生成 `review.txt` 的候选全文。模型只返回文本，不能指定路径、执行命令、直接写文件或批准自己的提案。应用继续负责展示和审批。

## 测试案例和通过标准

1. 在新的 App 沙盒中生成一个合成样本，含会议名称、原时间和每轮唯一的标记。不给模型参考答案。把原文和“把会议改到周四下午两点，其他内容不变”作为请求发送。不发送真实项目文件。
2. 将响应解析为一份有大小上限的 UTF-8 候选文本。拒绝无候选、超长、缺失原标记、改变无关字段或目标时间不符的结果；不能回退为硬编码提案来让测试变绿。
3. 证明候选来自远端响应：记录本轮运行编号、模型标识、服务端请求或响应 ID、候选摘要；不记录密钥、Authorization 头或完整环境。模型生成结束时独立读回，原文件仍应未变。
4. 对同一份候选复用现有 App 审批处理器：拒绝后 `fs/writeFile` 0 次且原文未变；允许后 1 次且写回与预览逐字节一致。CI 的模拟决定不等于真人点击。
5. 一次手动触发最多提交一次模型生成请求，限制输出长度，关闭自动重试。缺密钥、网络异常、鉴权失败、预算或配额不足均报告失败，不自动重跑。

## 凭据和边界

使用测试专用的 `OPENAI_API_KEY`，由仓库所有者通过 GitHub Actions Secret 设置。仅显式触发的可信工作流可以使用它，不给 PR、无关步骤、构建包或测试产物；模拟器通过受限中转或等效机制访问，禁止写入 App 包或命令行。模型请求与已验证的本地文件读写分开记录。如果通过 App 请求模型再让 Codex 执行写回，不能称为已经验证内嵌 Codex 的模型轮次；若验证官方模型轮次，则必须另有 `turn/start` 和完成事件证据。

本轮不涉及真机签名、TestFlight 或任意项目编辑。无凭据时保留现有无密钥回归，不作真实模型已运行的结论。
